# BOARD.md — Доска разработки проекта P05 «Классный штаб»

Обновлено: 2026-11-26 (Занятие 23 · финализация и рефакторинг)

## Паспорт темы P05
- **Название:** «Классный штаб» — школьная панель совета старшеклассников.
- **Подводный камень:** путаница `Date.prototype.getDay()` в JS (`0` = воскресенье, `1` = понедельник ... `6` = суббота); несколько массивов в одном JSON-состоянии (атомарная запись без затирания ключей); обработка `weathercode` и единиц измерения Open-Meteo; запрет персональных данных (телефоны и домашние адреса).
- **Идея защиты:** показать «Сегодня» с `aria-current="date"`, сменить дежурного с сохранением в `localStorage`, показать живую погоду Москвы (Open-Meteo) и переключение на честный фолбэк в `Offline`.

## Схема данных (`localStorage` ключ `p05-class-hq-v1`)

```json
{
  "notices": [
    {
      "id": "n1",
      "title": "Сбор макулатуры",
      "body": "Кабинет 12, принести перевязанные связки до 14:00",
      "date": "2026-11-27",
      "archived": false
    }
  ],
  "duties": [
    { "weekday": 1, "names": ["Алина С.", "Тимур К."] }
  ],
  "birthdays": [
    { "id": "b3", "name": "София К.", "className": "10А", "md": "03-21" }
  ],
  "settings": {
    "theme": "light",
    "glass": "on",
    "workdays": 5,
    "lat": 55.75,
    "lon": 37.62
  }
}
```

### Документация маппинга дней недели
В JavaScript метод `date.getDay()` возвращает:
- `0` — Воскресенье (в школьной сетке 5–6 рабочих дней не участвует; в интерфейсе выводится подсказка о ближайшем понедельнике)
- `1` — Понедельник
- `2` — Вторник
- `3` — Среда
- `4` — Четверг
- `5` — Пятница
- `6` — Суббота (отображается при включении режима 6-дневной учебной недели)

## Протоколы обязательного рефакторинга (2 сложные функции)

### 1. `validateNoPersonalData(text)` (и таблица `PII_RULES` + `validateTextField`)
- **Было:** разрозненные проверки регулярных выражений внутри обработчиков каждой из трёх форм, дублирующие логику и ложно срабатывавшие на даты вида `2026-11-27`.
- **Стало:** чистая функция без побочных эффектов с декларативной таблицей правил `PII_RULES` (`phone-pattern`, `digit-sequence`, `address-marker`) и безопасным исключением дат формата `ГГГГ-ММ-ДД` и `ДД.ММ.ГГГГ`.
- **Протокол проверки (4 тестовых набора):**

| Набор входных данных | Ожидаемый результат | Фактический результат | Статус |
| :--- | :--- | :--- | :--- |
| `"Кабинет 12, сбор в 14:00 (2026-11-27)"` | `ok: true, reason: null` | `ok: true, reason: null` | Совпало |
| `"Звонить +7 (999) 123-45-67 после уроков"` | `ok: false, reason: "phone-pattern"` | `ok: false, reason: "phone-pattern"` | Совпало |
| `"Отнести на ул. Ленина, д. 12, кв. 5"` | `ok: false, reason: "address-marker"` | `ok: false, reason: "address-marker"` | Совпало |
| `"Код домофона 1234567"` | `ok: false, reason: "digit-sequence"` | `ok: false, reason: "digit-sequence"` | Совпало |

### 2. `normalizeWeatherForecast(rawApiData, fallbackData, updatedAt)`
- **Было:** прямое чтение массивов Open-Meteo внутри `loadWeather()` отдельно от обработки фолбэка `{ "tmax": 12, "code": 2 }`.
- **Стало:** единая чистая функция нормализации со словарём кодов `WMO_WEATHER_MAP`, обрабатывающая двухдневный прогноз (индекс `1` — завтра), однодневный ответ, пустой ответ и компактный офлайн-фолбэк.
- **Протокол проверки (4 тестовых набора):**

| Набор входных данных | Ожидаемый результат | Фактический результат | Статус |
| :--- | :--- | :--- | :--- |
| Живой Open-Meteo на 2 дня (`tmax: [1, -3], code: [3, 71]`) | `status: "ready"`, `tmax: -3`, `icon: "icon-weather-snow"`, `yardOk: false` | Соответствует | Совпало |
| Живой Open-Meteo на 1 день (`tmax: [14], code: [0], precip: [10]`) | `status: "ready"`, `tmax: 14`, `icon: "icon-weather-sun"`, `yardOk: true` | Соответствует | Совпало |
| Сбой сети (`rawApiData: null`, `fallback: { tmax: 12, code: 2 }`) | `status: "fallback"`, `tmax: 12`, `description: "Переменная облачность"`, `yardOk: true` | Соответствует | Совпало |
| Пустой ответ API (`daily: { temperature_2m_max: [] }`) | `status: "empty"`, `data: null` | Соответствует | Совпало |
